# Требования к API возвратов

Сервис хранит заказы и заявки на возврат. Заказы уже созданы; добавлять и менять их через API не нужно. Авторизация в задании не требуется.

Все суммы передаются целыми числами в минимальных единицах валюты: `1500` означает 15 рублей или 15 долларов. Числовые строки, дробные числа и логические значения вместо суммы не допускаются.

## Данные

### Заказ — Order

| Поле | Тип | Ограничения |
|---|---|---|
| `id` | string | UUID |
| `amount` | integer | Больше нуля |
| `currency` | string | `RUB` или `USD` |
| `status` | string | `paid` или `unpaid` |

### Заявка — Refund

| Поле | Тип | Ограничения |
|---|---|---|
| `id` | string | UUID |
| `order_id` | string | UUID существующего заказа |
| `amount` | integer | Не меньше 1 |
| `currency` | string | `RUB` или `USD` |
| `reason` | string | От 3 до 200 символов |
| `status` | string | `pending`, `approved` или `rejected` |
| `created_at` | string | Дата и время в RFC 3339 |

В ответе с заявкой присутствуют все перечисленные поля. Новая заявка получает статус `pending`; `id`, `status` и `created_at` назначает сервер.

### Ошибка

Все ошибки API имеют одинаковую структуру:

```json
{
  "error": {
    "code": "refund_not_found",
    "message": "Заявка не найдена"
  }
}
```

`code` — фиксированный код из требований, `message` — непустое пояснение. Точный текст пояснения не фиксируется.

## Операции

| Метод | Путь | Результат |
|---|---|---|
| GET | `/health` | `200`, `{"status": "ok"}` |
| GET | `/orders/{order_id}` | `200`, объект Order |
| POST | `/refunds` | Создание заявки: `201`; повтор того же запроса: `200` |
| GET | `/refunds` | `200`, список заявок с пагинацией |
| GET | `/refunds/{refund_id}` | `200`, объект Refund |
| POST | `/refunds/{refund_id}/approve` | `200`, заявка в статусе `approved` |
| POST | `/refunds/{refund_id}/reject` | `200`, заявка в статусе `rejected` |

Параметры `order_id` и `refund_id` во всех путях имеют формат UUID. Успешные ответы с данными и ответы об ошибках передаются как JSON.

## Создание заявки

Тело `POST /refunds` содержит ровно четыре обязательных поля:

```json
{
  "order_id": "11111111-1111-4111-8111-111111111111",
  "amount": 1500,
  "currency": "RUB",
  "reason": "Возврат товара"
}
```

Дополнительные поля запрещены. Ограничения `amount`, `currency`, `reason` и формата `order_id` совпадают с описанием данных выше.

Обязателен заголовок `Idempotency-Key`: от 8 до 64 символов, только латинские буквы ASCII, цифры, `_` и `-`.

Правила обработки:

1. Заказ должен существовать и иметь статус `paid`.
2. Валюта заявки должна совпадать с валютой заказа.
3. Сумма всех `pending` и `approved` заявок по заказу вместе с новой заявкой не должна превышать сумму заказа. Заявки `rejected` в расчёт не входят.
4. Проверка доступной суммы и сохранение заявки выполняются атомарно. Два одновременных запроса не должны превысить лимит заказа.
5. Первый успешный запрос с ключом создаёт заявку и возвращает `201`, объект Refund и заголовок `Location: /refunds/{id}`.
6. Повтор с тем же ключом и теми же значениями полей возвращает `200`, ту же заявку с тем же ID и `Location`. Новая строка и повторное резервирование суммы не создаются. Порядок полей JSON значения не имеет.
7. Если с уже использованным ключом пришло другое тело, сервер возвращает `409` с кодом `idempotency_conflict`.

| Ситуация | HTTP-код | `error.code` |
|---|---|---|
| Заказ не найден | 404 | `order_not_found` |
| Заказ не оплачен | 409 | `order_not_paid` |
| Валюты не совпадают | 409 | `currency_mismatch` |
| Превышена доступная сумма возврата | 409 | `refund_limit_exceeded` |
| Ключ использован с другим телом | 409 | `idempotency_conflict` |
| Некорректное тело или заголовок | 422 | `validation_error` |

## Получение заказа или заявки

`GET /orders/{order_id}` возвращает Order. Если UUID корректен, но заказа нет, ответ — `404`, `order_not_found`.

`GET /refunds/{refund_id}` возвращает Refund. Если UUID корректен, но заявки нет, ответ — `404`, `refund_not_found`.

## Список заявок

Параметры запроса для `GET /refunds`:

| Параметр | Обязательный | Значение по умолчанию | Ограничения |
|---|---|---|---|
| `status` | Нет | Все статусы | `pending`, `approved`, `rejected` |
| `limit` | Нет | `10` | Целое число от 1 до 100 |
| `offset` | Нет | `0` | Целое число не меньше 0 |

Ответ:

```json
{
  "items": [],
  "total": 0,
  "limit": 10,
  "offset": 0
}
```

`items` содержит объекты Refund. `total` — число всех заявок после фильтрации по статусу, до применения `limit` и `offset`. Если фильтру не соответствует ни одна заявка, `items` пустой и `total` равен 0. Если `offset` выходит за конец списка, `items` тоже пустой, но `total` сохраняет число найденных заявок.

Порядок стабилен: сначала по `created_at` по возрастанию, при одинаковом времени — по `id` по возрастанию.

## Подтверждение и отклонение

Операции `approve` и `reject` выполняются без тела запроса. Менять статус можно только из `pending`:

| Текущий статус | Операция | Новый статус |
|---|---|---|
| `pending` | `approve` | `approved` |
| `pending` | `reject` | `rejected` |

Любая попытка изменить `approved` или `rejected` возвращает `409`, `invalid_status`, в том числе повтор уже выполненной операции. Для отсутствующей заявки ответ — `404`, `refund_not_found`.

После отклонения сумма заявки снова доступна для новых возвратов по заказу. Подтверждённая заявка продолжает учитываться в лимите.

## Валидация

Некорректный UUID в пути, недопустимые параметры запроса, отсутствие обязательного заголовка, неверный JSON и нарушение ограничений тела дают `422`, `validation_error`, в общей структуре ошибки. В ответе не должно быть стандартного поля FastAPI `detail` вместо `error`.
